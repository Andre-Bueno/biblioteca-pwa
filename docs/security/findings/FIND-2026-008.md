## Resumo
`FastAPI(...)` mantem `redirect_slashes=True`: `GET /api/v1/items/` responde `307` com `Location` montado a partir do `Host` recebido, sem autenticacao previa. Alem disso, o redirect usa `http://` mesmo atras de TLS se o esquema nao for confiavel.

## Como reproduzir
`GET /api/v1/items/ HTTP/1.1` + `Host: evil.com` (socket cru, instancia 18703): `307 Temporary Redirect`, `location: http://evil.com/api/v1/items`. Com `Host: x`: `location: http://x/api/v1/items`. Tambem `POST /api/v1/auth/login/` (sem token): `403` (CSRF antes do redirect, bom) e `GET /api/v1/items/{id}/pages/0/` -> `307` (`no-store`).

## Evidencia
Resposta observada (cabecalhos): `location: http://evil.com/api/v1/items`, `cache-control: no-store`. `backend/app/main.py:22` nao define `redirect_slashes=False`.

## Impacto
Baixo: um navegador nao permite o atacante escolher o `Host` da vitima; exploracao exige proxy/cache que respeite `Host` do atacante (cache poisoning, mitigado por `no-store`) ou cliente nao-navegador. Gera 404/redirects ambiguos para caminhos da API e dois URLs para o mesmo recurso.

## Correcao recomendada
`FastAPI(..., redirect_slashes=False)` (a API e consumida por URLs exatas) e, se mantiver, validar `Host` contra uma lista (`TrustedHostMiddleware` com host do deploy).

## Criterios de aceite
- [ ] `GET /api/v1/items/` com Host arbitrario nao produz `Location`
- [ ] Teste de regressao `tests/regression/test_reg_013_no_trailing_slash_redirect.py` criado e verde
- [ ] `scripts/check` verde
- [ ] Mapas/CHANGELOG atualizados

## Correcao aplicada (corretor, working tree)
`redirect_slashes=False`. Teste: reg_013.
